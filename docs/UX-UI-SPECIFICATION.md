# Inkloom UX/UI 规范与本轮验收范围

版本：3.1.0。更新：2026-11-14。

## 设计目标

简洁、轻快，保留完整功能，通过默认视图、图标、页签和渐进展开减少同时呈现的信息。**全面执行「表层极简 · 菜单收纳（Minimalist Surface, Menu-Driven Disclosure）」原则**：主界面与各工作区顶栏仅保留最高频的核心主操作，所有次级工具、视图预设管理、图谱寻路器、牌组筛选与制卡、原件阅读辅助功能一律收纳进统一的轻量弹出菜单（`.ux-popover-menu`），拒绝在界面上平铺堆叠控件。参考 Obsidian 的笔记工作区组织方式，在此基础上建设有来源的知识整理与智识工具。

本规范替代此前“黄金法则”：不强制所有工具使用固定 295px 双栏，不把所有选项做成彩色胶囊，不要求长正文全部塞进首屏，不声称未经测量的效率提升或空间占比。

## 空间与组件

- 根节点保持满高纵向布局；顶栏和活动栏属于稳定外壳，内容区按需滚动。工作台、研究、智识与插件视图不使用文章最大宽度限制。
- 全局设置仅保留活动栏底部常驻入口，文件菜单可打开同一窗口；顶栏及各页面不再复制设置按钮。“导入与库管理”使用向下箭头，与设置区分。
- 七组设置使用原生折叠控件，一次展开一组；主题包与外观扩展默认收起。长设置内容正常滚动，不收缩分类或裁切内容来强塞首屏。
- 客户端、源码和阅读底色均使用 16px 色签，按标签自然宽度排列，窗口不足时换行；不以裁切、缩字或大色板掩盖布局问题。
- 研究页使用视图页签、查询与操作、结果区的层次。无资料和无匹配结果分别提供登记与清除筛选；窄屏资料标题整行显示，元数据使用两列。
- 导航表示位置，页签表示视图，标签表示筛选，按钮表示命令。颜色用于选中、状态和少数语义重点。
- 页面区段使用无框布局与分隔线。独立条目可用卡片，卡片内不继续套卡片。
- 工具使用 Lucide 图标和可访问名称。说明不是常驻长段落；必要时用提示和用户手册。
- 长笔记标题允许换行。路径选择使用明确字段，不靠标题中的斜线猜测目录。
- 窄工作区表单自动转为单列；390px 下智识导航改用包含全部功能的分组菜单。
- 浮层仅在需要时显示，位置限制在视口内。不能用整体裁切掩盖越界控件。
- 深色主题同时调整底色、文字、分隔线与悬停颜色，不能只替换背景。
- 客户端色系和颜色按钮共用同一切换路径，停用外观包覆盖并同步两栏明暗；外观包预览不会改变设置/错误弹窗的宿主色彩。
- 新配置默认启用「墨图云灰（`neutral`）」与「浅灰（`gray`）」双栏纸面，使用 14px 工具图标、15px 正文、1.75 行距；不覆盖升级用户保存过的排版偏好。按钮密集条（活动栏胶囊、顶栏操作条、知识库操作条、笔记脉络操作条、编辑器工具条）采用微凸起深色炭黑胶囊（`--charcoal-bar-bg`）配纯白线条图标（`--charcoal-bar-ink`），取消杂乱八色按钮。
- 玻璃表面由带 alpha 的颜色和细高光边组成，透出的是应用内主题底色；弹窗保持足够实底。不把渐变传给 `color-mix`，不宣称 Windows 窗口透视。
- 浏览器布局适配不等于手机原生应用支持。Windows 宿主使用隔离 profile 验收。

## 数据真实性

首页热图统计有效的笔记记录日期，不是编辑次数或用户在线活动。缺失日期计入“未标日期”，不补造历史。

认知演进页同样只使用记录中的有效日期，缺日期不进入时间线；取消固定历史日期、强制上升曲线、虚构引用与零曲率的伪造替代值。图结构和文本差异仅是规则指标，不是个人成长、认知质量或观点确已改变的证据。

OneNote 初始状态为未连接；明确选择文件后才解析。浏览器只预览，Windows 写入完成后才报告成功。未拿到原附件字节时不得生成占位图片/PDF。部分成功必须报告已写入数量和失败原因，不承诺复杂自由画布无损迁移。

图谱 `EXTRACTED` 表示原文中实际存在双链，`INFERRED` 表示同标签规则产生的关联；它们不是真实性概率。来源按钮打开对应笔记，旁边显示索引时的行号；不冒充精准光标定位。推断关系不能自动变成原文结论。

## Graphify 对标

| 方面 | Inkloom 当前 | Graphify v8 文档所述 | 决策 |
| --- | --- | --- | --- |
| 基本对象 | 笔记、显式双链、同标签关系 | 源码/文档抽取的实体与语义关系 | 不把两者称为同一种图谱 |
| 关系出处 | 本轮增加文件、行号、显式/推断区分 | `source_file`、`source_location`、关系类型与证据等级 | 优先采用可追溯原则 |
| 分析 | PageRank、标签传播社区、最短路径 | NetworkX 分析、Leiden，特定环境回退 Louvain | 不为对齐名词而替换已有算法 |
| 文档语义抽取 | 已支持笔记/章节/粗体概念实体关系抽取、原位审阅及 `source_fingerprints` 证据失效重算 | 语义抽取需要配置模型/助手 | 规则抽取与人工审阅分离，不自动把推断写回原文 |
| 使用方式 | Windows 本地工作台，默认离线 | 多阶段抽取、构图、聚类、分析和导出管道 | 未集成 Python 后端，未上传笔记 |

后续路线按“出处可靠 → 关系审阅 → 概念实体抽取 → 变更后证据失效/重算 → 可解释认知路径”推进（1.8.0 已落地概念实体抽取审阅、原文变更证据失效重算与寻路每跳证据链）。标签相似、图中心性与认知质量不是同一个量，不能用物理学名称或百分比替代验证。

## 验收方法

1. 每项说明真实执行方式、输入、预期、实际、保存后回读与环境。浏览器使用独立 profile，Windows 使用测试 Vault。
2. 运行 `tools/verify-phase2.mjs --ux`，以及同脚本的 `--exe <候选EXE> --ux`。报告记录版本、环境、网络请求、失败与截图。
3. 覆盖 1440、1280、960、390px，浅色/深色，长标题、八级目录、真实拖动、键盘、刷新记忆、返回正文、取消和失败。
4. 逐页检查十五个智识面板的布局与导航；没有配置模型时不发起外部模型请求，也不声称完成模型评测。
5. 对首页、写作、迁移各步、编译器、演进史、闪卡、图谱及异常视图截图目视复核。发现问题修复后复测同一项。
6. 保留既有创作、规划、工作台、外观、核心、原生存储与发布包回归。UI 成功不能覆盖数据安全失败。

发布结果以 [发布报告](../verification/release-results.json) 的版本和哈希为准；[浏览器 UX](../verification/ux-browser-results.json) 与 Windows UX 报告只说明各自执行范围。未验证的外部服务和窗口能力不得写为全量通过。
