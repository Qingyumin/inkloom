# 0.5.2 创作与研究

本版交付本地白板、只读内容引用和资料研究工作组，不包含云协作、AI、网页全文采集或引文管理器。正式验收以同版本报告及发行包哈希为准，浏览器与Windows结果分别记录。

## 白板

1. 活动栏选择“白板”，填写名称后新建。形状、文字、连线、手绘和内嵌图片由Excalidraw 0.18.0处理。
2. 绘图变化立即进入活动Markdown草稿；点击保存或在画布中按Ctrl+S才提交。保存期间临时禁止继续操作，失败保留错误与草稿。
3. “查看白板源文”回到Markdown；“所有白板”打开列表。场景是唯一的excalidraw代码块，前后的说明、双链与属性保留。
4. 导入接受Excalidraw JSON；导出支持Excalidraw、PNG和SVG。PNG最长边2400像素。编辑器与字体按本地资源加载，不调用官网服务。

场景最多6MiB文本、3000元素、60张内嵌PNG/JPEG/WebP、每笔画20000点。网页嵌入、远程图片、云协作和AI功能不提供。元件库属于profile设置，受131072字符预算约束，不是Markdown的唯一内容副本。场景保存背景和网格模式，不保存视口、选区。缩放窗口后适配内容，普通绘制不持续自动缩放。

再次打开会使用原场景，初始规范化不单独制造未保存状态。退出、停用插件不会删除场景。外部草稿版本变化时同步或阻止覆盖；格式损坏时保留源文，需在源码修正后重新打开。限制不是任意复杂图在所有机器上流畅的保证。

## 内容引用

独立一段输入 `![[笔记]]`、`![[目录/笔记#章节]]` 或 `![[笔记#^块标识]]`。预览只读，点击来源打开原文；标题按层级截取，块按显式标识选择，代码示例不被当作标记。行内写法保留链接，不渲染完整预览。

将光标置于正文段落，通过文件菜单“复制段落引用”生成或复用 `^block-...`。标记是普通Markdown草稿的一部分，仍需保存。含保留分隔符的文件名拒绝生成错误链接。复制/删除标记可能产生重复或失效；本版不提供隐藏块数据库、双向编辑或跨复制自动改号。

最多24个顶层预览；每个引用树最多3层、24个展开项、80000字符。导出整篇共享24项/80000字符预算。缺失、歧义、循环或超过预算明确提示并阻止不完整导出。Word/PDF/HTML共用临时展开源文，原始笔记不被改写；实际文件覆盖范围见测试报告，不将HTML通过等同于所有Office分页通过。

本地相对图片按被引用笔记的目录重定位；浏览器副本没有原生文件访问权，需将图片内嵌。远程引用图片不自动下载。白板代码块嵌入显示源数据，不是白板缩略图。

## 研究资料

1. 活动栏“研究”中登记标题、类型、来源地址或标识、作者、年份与说明。网页类型只接受无凭据HTTP(S)地址；未知作者和年份留空。
2. 保存为sources目录中的普通Markdown，category为source。按资料、札记、摘录或全部筛选，每页25条；搜索覆盖标题、作者和来源标识。
3. 可将阅读状态改为待读、阅读中或已读。状态写入前读取当前版本，脏笔记或冲突不会被后台静默覆盖。
4. 资料行的札记按钮新建reading目录笔记，包含来源永久ID和真实路径双链。登记草稿按库保存在profile，保存失败会显示错误。
5. 在正文或源码中选中最多20000字符，文件菜单选择“选段摘录到研究”。先保存来源块位置，再独占创建excerpts笔记；摘录保留原选文字面快照与来源块链接。

来源保存取消或失败时不创建摘录。摘录创建失败时已经保存的块标记保留，不回滚其他源文编辑。路径改名使用既有双链更新规则，删除源段不会删除摘录快照。阅读札记和摘录不是自动核实的学术引用；作者、年份和判断均由用户负责填写。

## 复用与许可

Excalidraw 0.18.0、React/ReactDOM 18.3.1使用MIT；字体按各自MIT或SIL OFL文本保留。8族233个WOFF2文件有逐文件SHA-256，未使用的旧Liberation服务器字体不进入发行包。字体资源增加包体，不以按需加载宣称没有磁盘成本。

构建生成 [依赖许可清单](../licenses/bundled/manifest.json)，记录固定包版本、实际输入与哈希；字体清单见 [字体清单](../licenses/whiteboard-fonts/font-manifest.json)。部分npm包不附完整许可，补充方式与未记录历史提交的边界见 [许可补充说明](../licenses/upstream-overrides/README.md)。普通构建和运行不下载这些文本。未做空node_modules下的完整npm ci，也不宣称已经过全面法务审查。

## 验证

在隔离profile和合成知识库执行，不访问正式Vault。运行 `node tools/verify-phase2.mjs --creation` 验证浏览器；追加 `--exe release/Inkloom-0.5.2/Inkloom.exe` 验证Windows包。每个报告含具体检查、实际结果、截图和外部请求列表；失败报告保留到对应版本退出保留窗口。

创作组覆盖：引用边界和源文不变、实际画布绘制/保存/重开、资料登记/阅读状态/札记/摘录回读、中文文字/撤销/图片字节保留，以及窄屏非空像素。另有500个简单图形的导入和追加绘制、保存后重启回读与插件停用/重启用检查，分别以20秒打开、8秒单次绘制流程为测试上限，不是帧率承诺或3000元素全类型压力认证。浏览器另外下载并解析展开HTML与Excalidraw/PNG/SVG，重导入JSON；这不代替Windows原生保存对话框的人工交互验证。

86项核心测试包含引用、场景校验、SDK权限和研究分页；完整发行还要求原生存储、任务规划、工作台、外观、旧功能与百/千/万篇性能报告。真实IME输入、隔夜运行、物理断电、任意第三方文件和所有Office逐页兼容仍不在自动化通过结论中。最终是否通过查看 [发行报告](../verification/release-results.json) 中的版本与门禁结果，不能用旧版报告代替本版。
