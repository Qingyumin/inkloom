# Inkloom 0.3 验证说明

## 环境与证据

Windows、独立浏览器和真实WebView2 EXE；测试创建独立profile，不连接正式Vault。0.3.1浏览器检查使用Chrome，Edge在页面加载前连续退出的记录保留；实际环境以报告browserChannel为准。正式EXE不提供window.inkloomTest。最新报告：[浏览器](../verification/phase3-browser-results.json)、[真实EXE](../verification/phase3-desktop-results.json)、[性能](../verification/benchmark-results.json)。报告记录版本、时间、操作、截图和EXE哈希，历史失败现场不覆盖。

运行命令在 [README](../README.md)。桌面专项执行过程中的临时文件只位于报告目录内的 profile/StarterVault，成功后退出自己启动的进程并尝试删除该 profile。失败时保留现场，不强关用户窗口。

0.3.4新增14项同步服务/缓存/客户端测试：用可控Promise阻塞缓存加载或提交、假时钟触发计算预算，验证旧请求不发布、加载取消后仍能恢复缓存、同ID跨库与同库重建、失败不阻塞后续队列、缓存封装拒绝损坏、超时和Worker错误后重建。客户端与真实同步服务联测先接受原文，再暂停一次变更提交，此时撤回编辑或恢复删除；最终索引、关系和缓存必须回到原文基准。有效缓存恢复时写入次数为0，后续单篇变化只写回对应ID。客户端预算检查使用10ms测试值，不把它当生产耗时指标。

新缓存使用Web Crypto SHA-256及结构检查发现意外损坏，不是对能重算校验和的恶意篡改提供认证。协作式20秒预算在批次与关键等待处检查；单次同步解析不能由自身中断，客户端30秒预算会终止Worker。0.3.8新增错误表结构重建与查询硬超时恢复；没有宣称穷尽全部大文件和存储组合。

## 0.3.5 写入与回滚

由 [原生测试脚本](../tools/test-native.ps1) 编译执行 [测试夹具](../native/VaultStoreTests.cs)，不是页面按钮测试。每次在临时目录新建独立profile与Vault，结束后清理临时目录。报告保留版本、七个新增检查及源码/测试文件哈希：[原生报告](../verification/native-results.json)。测试编译启用INKLOOM_TEST，正式构建不启用；发行校验通过反射确认两个故障点属性不存在。

回滚共用数据：First.md为带BOM的`# First\r\n`，Ref.md为无BOM的`[[First]]\r\n`，高亮文件为`{"marks":[]}`。调用ApplyRenamePlan，目标Next.md，两个更新分别为`# First\n`到`# Next\n`、`[[First]]\n`到`[[Next]]\n`；预期原文使用更新前内容。失败后逐字节回读两篇、高亮文件、名称、永久ID与日志标记，再重新打开相同profile核对待恢复数量。

| 场景 | 执行方式 | 预期与回读 |
| --- | --- | --- |
| 引用文件占用 | 用FileShare.Read持有Ref.md，真实系统文件占用阻止替换，再提交改名 | 已写入的First.md恢复，Ref.md未变，名称/ID/高亮未丢；写ROLLED_BACK，无待恢复项 |
| 高亮文件占用 | 用FileShare.Read持有高亮文件，正文改名后高亮移动失败 | 正文名称与全部引用恢复，高亮留在原处，写ROLLED_BACK |
| 身份迁移后失败 | 测试故障点在MoveIdentity完成后抛IOException | 名称、原文、高亮与永久ID回到基准，写ROLLED_BACK |
| 回滚中独占文件 | 写完正文后，测试故障点将Ref.md改为EXTERNAL_VERSION并用FileShare.None占用，再抛错 | Ref.md外部版本保留；回滚继续恢复First.md，保留1项待恢复与recovery.json，不写终态标记 |
| 回滚中外部修改 | 写完正文后将Ref.md改为EXTERNAL_VERSION，再由测试故障点抛错，不加锁 | 不以备份覆盖外部版本；其他文件恢复，1项待恢复，备份保留 |
| 单篇校验后被修改 | First.md为带BOM的`# First\n`，调用UpdateFileSource写`# Replacement\n`；原文校验后由故障点写入带BOM的`EXTERNAL_AFTER_VERIFICATION\r\n` | 提交前比较拒绝写入，外部正文、BOM和CRLF原样保留 |
| 改名校验后被修改 | 对单篇First.md提交改名到Next.md，更新`# First\n`到`# Next\n`；校验后注入同样外部版本 | 拒绝改名与覆盖，原名称和外部内容保留 |

只有前两项直接利用操作系统文件共享冲突，其余明确为确定性故障注入；它们不代替断电、强制结束进程或全部ACL权限验证。recovery.json写入失败时仍保留未完成状态和已有备份，不能保证只读或故障磁盘上一定写出诊断。最后一次比较与系统原子替换之间仍存在外部修改窗口，未宣称跨程序事务锁。

## 0.3.6 知识库管理

本轮合并安全切库、恢复管理与扫描诊断。原生专项扩展在同一测试夹具中；真实EXE操作进入设置的“知识库与视图”，不依赖生产测试API。浏览器仅展示副本与扫描信息，原生路径和恢复按钮禁用。

| --- | --- | --- |
| 切库失败回退（原生） | 测试目录内创建原库并星标笔记；目标库identity.json写入非法JSON后调用SetVaultDirectory；另用FileShare.Read占用vault-state.json再切库 | 两次均拒绝；当前路径、库ID、笔记ID与星标不变，重开profile仍指向原库 |
| 实际路径切库（EXE） | 测试profile下创建ManagedVault，含带BOM/CRLF的First.md和引用它的Ref.md；设置中输入完整路径并按Enter | 导航2篇，编辑器打开First.md，旧干净会话关闭 |
| 未保存内容与失败路径（EXE） | First末尾输入UNSAVED_SWITCH_CHECK，设置中尝试打开空库；关闭设置检查文字；撤销并保存后尝试不存在的路径 | 未保存时阻止切库、文字保留；不存在的路径提示错误且仍为原库 |

| 预览过期（EXE） | 预览后外部将Ref.md改为EXTERNAL_BEFORE_CONFIRM，再勾选并恢复；回读磁盘 | 拒绝旧预览，不覆盖外部正文；恢复测试基准后重新预览才可提交 |

| 分页与旧记录（EXE） | 在测试profile构造26条旧日志，刷新待恢复记录并翻页，选中旧记录 | 第一页25条、第二页1条；旧记录提示缺少校验值并禁止恢复，测试后清理构造记录 |

原生恢复专项另覆盖：同ID跨库拒绝、坏备份、备份路径越界、旧格式只读、独占文件导致部分恢复后重试、永久身份与高亮保留，以及27条待恢复记录的25/2分页。预览DTO不返回备份字节或内部日志对象。日志和输出SHA-256不构成本地攻击者认证，预览后再次校验也不能消除最后一次读取到系统写入间的全部竞争。

记录分页为每页25条，原生接口每次最多100条；恢复检查单文件上限24 MiB、备份累计96 MiB、清单8 MiB。完成或已回滚事务不再次恢复，恢复只允许当前库。异常提示中的详情入口进入同一管理分组。

## 性能口径

0.3.7新增启动专项：原生测试创建Alpha/Beta两篇，记住Beta后重新构造VaultStore并核对“继续上次”；指定Beta后移动为Moved并核对永久ID定位；删除目标后回退Alpha；空白模式返回无笔记。占用identity.json时保存偏好必须拒绝且内存回退。不同库偏好隔离，最近记录去重限12条，移除入口不删目录，失效当前库回退且旧路径保留为不可用。

真实EXE专项在0.3.6管理场景形成的ManagedVault中，通过设置保存“指定Ref.md”“继续上次并打开First.md”“空白”三种模式。每次使用现有finishClose命令正常关闭自建测试进程，再以相同隔离profile重新启动新进程；分别回读文件名、设置值、空白正文与笔记计数。最近列表打开回StarterVault后移除ManagedVault入口，核对目录仍存在。该测试包含三次真实进程重启，不是页面reload，也不代表真实断电恢复。既有Recovered会话优先分支保留，但本轮未新增强制崩溃恢复测试。

固定种子 `inkloom-20261022-chain-v1`，100/1,000/10,000 篇短笔记，以链式双链和十组标签构造。报告保存机器、Node/系统信息、数据集哈希和源文件哈希。

旧算法对比指保留的同步全量图谱函数，不是旧 EXE 全流程对比；每个样本独立 Node Worker，20 秒超时记 budget-exceeded。增量编辑测九次，浏览器使用真实 CodeMirror 输入并等待索引反馈。页面就绪包含首次资源与索引准备；图谱成本包含后台布局和返回显示，不等于每帧耗时。

内存字段为 JS heap，不是原生 EXE+WebView2 总工作集。合成短笔记通过不能代表多媒体大库、真实中文长稿、磁盘权限异常或所有硬件。万篇图谱触达 2.5 秒预算时明确记录 budget-limited。

0.3.2基线新增实际表格分页：每档打开50条第一页，切到下一页，再改25条，搜索最后一篇并验证自动回到1/1，最后关闭并确认DOM卸载。`tablePaginationMs`包含上述打开和分页操作，不是单次查询服务延迟；每页行数和卸载结果独立记录。

0.3.3基线记录图谱切走后的真实Worker数，仅允许仍显示的局部Worker留存；停用知识图谱后必须为0。`graphDisableMs`与已结束Worker单独记录，不用插件布尔开关代替资源回收证据。

0.3.4每档新增`warmCache`：输入后先保存并回读，完成既有交互后在相同浏览器上下文重载，保留笔记版本并恢复初始显示设置。要求全部缓存命中、零重解析、无告警，并记录页面就绪耗时；不是只测SHA-256或磁盘读取。测试夹具仅首次导航写入样本，不能在重载时覆盖刚保存的原文。

## 0.3.8 收口验收

| 项目 | 执行方式与数据 | 预期与回读 |
