# 0.5.1 任务规划与滚动保留

日期：2026-10-24。Windows x64预览版。0.5工作台与文件保护继续保留；本次完整交付的是本地任务规划组，不代表白板、正文嵌入或全部0.5路线完成。

## 页面操作

1. 工作台的任务区域切换清单/看板；看板为未开始、进行中、已完成三列。任务可跨列拖动，也可使用状态下拉，键盘用户不依赖拖拽。
2. 点击任务铅笔或日历事件编辑标题、状态、日期、时间、优先级和重复规则。取消不写入；保存前回读原文与版本。标题修改为纯文字，未修改的标题保留原Markdown标记。
3. 日历事件可以拖到另一日期，保存失败时还原位置。已完成事件不允许拖动；编辑重复任务日期会以新日期重置该任务的后续规则起点。
4. 快速收集支持不重复、每天、工作日、每周、每月、每年，间隔1至365、每周星期组合和截止日期。未选择星期时按起点所在星期。

## 状态与重复规则

状态直接写入Markdown：`[ ]`未开始、`[/]`进行中、`[x]`已完成。其他Markdown编辑器可能将`[/]`显示为原文；不是新增私有任务数据库。

```markdown
- [ ] 周复盘 @due(2026-10-26) @repeat(weekly) @every(2) @days(MO,WE) @start(2026-10-26) @until(2027-01-31)
```

重复计算使用RRule 2.8.1，不自行实现日期算法。规则按原计划日期推进，而不是按点击完成的日期跳过积压；每次完成最多生成一条后续记录，不批量补建历史。截止日期包含当天。月末不存在的日期跳过，例如1月31日每月重复的下一次是3月31日；2月29日每年重复会跳过非闰年。

规则以浮动日历日期计算，提醒时间按本机时区解释；不处理跨时区协作、夏令时业务策略或应用关闭后的提醒服务。起点到当前任务日期最多支持100年跨度。

完成重复任务时，在同一Markdown提交中标记原记录完成，并在其列表内容之后插入下一次任务。原任务正文和子任务留在原记录，不复制为新实例。系统使用`@task`、`@next`、`@after`记录实例关系，界面不展示这些内部字段。

撤销只删除仍与系统生成内容一致、未完成且未追加正文的后续实例；如果后续实例已修改、完成、缺失或身份冲突，整次撤销拒绝，原文不变。带后续实例的已完成记录需先安全撤销，再修改其规划字段。普通任务仅变更状态时仍只替换状态字符。

任务改动复用统一版本化写入。含未保存编辑、外部源文变化或重复字段时拒绝；关闭插件不回滚已经提交的保存。旧索引缺少任务规划字段时从原文重建。

## 保留规则

只在发布包通过验收后滚动保留最近两个版本。范围为本项目的release和verification目录，包含旧截图、失败测试现场和测试profile；不包含源码、测试脚本、正式Vault、Logo或冻结依赖快照。

清理工具先验证最新EXE与ZIP哈希，再按版本号规划，未知归属不静默删除；旧EXE不可写时先停止，要求用户自行关闭，不强杀进程。发布门禁自动调用清理；也可先预览：

```powershell
node output/inkloom/tools/prune-releases.mjs
node output/inkloom/tools/prune-releases.mjs --apply --summary
```

每版最终发布报告按版本归档，随其对应测试一起保留。本文中的旧案例是行为说明，不要求保留所有历史二进制或截图。

## 复现验收

使用隔离浏览器上下文或脚本自动创建的Windows测试profile，不使用正式知识库。

```powershell
node --test --test-reporter=tap output/inkloom/core/*.test.mjs
node --test --test-reporter=tap output/inkloom/tools/prune-releases.test.mjs
node output/inkloom/tools/verify-phase2.mjs --planning
node output/inkloom/tools/verify-phase2.mjs --planning --exe output/inkloom/release/Inkloom-0.5.1/Inkloom.exe
```
